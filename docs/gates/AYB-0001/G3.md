## 4 Divergencias de los ADR del proyecto con la estrategia corporativa (se informan, no bloquean)

- **ADR-001**: el PLT-05 (DoR de planificacion, comite del 16-oct-2026)
  propuso Node.js 20 + NestJS como stack de la plataforma. ADR-001 decide
  construir sobre Spring Boot/Java y el Aybar SDK porque el scaffold del
  servicio ya existia en ese stack antes de esa reunion. Se informa al TL
  para que decida si hace falta comunicar el cambio al equipo que redacto
  el PLT-05.
- **ADR-002, ADR-006**: proponen un object storage con bloqueo de escritura
  (tipo S3/Object Lock, como sugiere el DoR PDF) pero este proyecto no
  tiene todavia un ADR de proveedor de nube — el SDK es neutral de nube por
  diseno. El TL debe confirmar el proveedor antes de que estas dos
  decisiones puedan pasar de `propuesto` a `aprobado`.
- **Costo cloud**: ningun ADR de este envio trae una cifra de costo real
  (ADR-001, ADR-002, ADR-006, ADR-008 lo dejan explicito como pendiente).
  El marco exige "impacto en costo cloud estimado, con numero y fuente"; no
  se inventa un numero sin decision de proveedor.
